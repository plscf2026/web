## 3. Finding-by-Finding Triage & Remediation Decisions (`F-01` to `F-33`)

- **F-01 (`SECURITY DEFINER` RPCs):** **REAL.** Revoke `PUBLIC`/`anon`, grant `authenticated`/`service_role`, enforce `current_admin_role()`/`current_event_staff_role()`, keep public-only RPCs (`rpc_get_public_governance_settings`, `rpc_get_public_reunion_stats`, `rpc_lookup_ticket`, `rpc_lookup_donation`, `rpc_verify_student_qr`, `rpc_verify_student_id`, `rpc_reserve_student_id`, `rpc_release_student_id_reservation`, `rpc_get_financial_transparency_summary`, `rpc_verify_personal_donation_history`, `rpc_resolve_login_email`). Fix in Migration 1 (`20270322000000`) with rollback.
- **F-02 (`USING (true)` RLS + backup tables):** **REAL.** Replace all permissive `(true)` policies listed above, drop un-dropped legacy policies (`staff_accounts`, `admin_accounts`, `staff_expenses`, `financial_ledger`, `expenses`, `donations`), preserve public `SELECT` on `gallery_media` & `about_contact_content` & public `INSERT` on `inquiries`, enable RLS + revoke `anon`/`authenticated` on the 3 backup tables if present. Fix in Migration 1 (`20270322000000`).
- **F-03 (`verify-student-id` Edge Function):** **REAL.** `verifyStudentTicket()` (`supabase.ts:1378`) already uses `rpc_verify_student_qr` first for public QR URLs; `verify-student-id` is only fallback / `SupabaseService.verifyStudentId`. Add JWT auth (`supabase.auth.getUser`) + `admin_accounts`/`staff_accounts` active role verification, validate inputs strictly and replace `.or()` interpolation with exact `.eq()` calls, require `qrToken` verification when provided or enforce token check on QR checks, and remove `qrToken` from any unverified payload. Check unit tests importing/mocking it!
- **F-04 (`localStorage` test session bypass in production):** **REAL.** `supabase.ts:1999-2010` & `eventStore.ts:613-624`. Gate `plscf_test_admin_session` / `plscf_test_staff_session` strictly inside `if (import.meta.env?.DEV && isDevTestBypassAllowed())` (also check `loginAdmin` / `loginStaff` writes so prod doesn't depend on spoofable localStorage).
- **F-05 (`parentFee` 1500 vs 500 mismatch):** **REAL.** `rules.ts:315` and `PaymentModal.tsx:79` hardcode `1500`, `manualRegistrationService.ts:361` defaults `1500`, whereas migrations `20270310` & `20270320` seed `500` and `store.ts:181` seeds `500`. Update `calculateTotalFee` to read `feeSettings.parentFee ?? 500` and `PaymentModal.tsx` to read `AppStore.getFeeSettings().parentFee` (or prop `parentFee`), without touching DB `portal_fee_settings`. Report seeded value (`500`) + provide readonly check for live value.
- **F-06 (Gallery SVG upload & unsanitized links):** **REAL.** `GalleryManagementTab.tsx:220` allows `image/svg+xml`; `GalleryPage.tsx:229,256` renders un-sanitized `thumbnail`/`videoUrl`. Enforce `readValidatedImage()` (JPG/PNG/WebP + `createImageBitmap`) in `GalleryManagementTab.tsx` and apply `sanitizeUrl()` (allowing `https:` / `/` / safe data image URLs via `sanitizeImageUrl` for thumbnails and `https:`/`http:`/`mailto:`/`/` via `sanitizeUrl` for `videoUrl`) in `GalleryPage.tsx` and `GalleryManagementTab.tsx`.
- **F-07 (Closed-browser donation IPN gap):** **REAL.** `20270312:623-636` updates `pending_orders` only. Fix in Migration 2 (`20270322010000`) updating `rpc_promote_pending_order_to_registration` (and `rpc_handle_paystation_ipn` `ipn_logs` write!) to idempotently insert/upsert into `donations` (and `donations_2027` + `financial_ledger` if present) using normalized net `donationAmount` from `v_order.fees->>'donationAmount'`, `p_trx_id` anti-replay safe! Also add readonly query in `readonly_checks.sql` listing paid-but-unrecorded `pending_orders` (`order_type='donation'`).
- **F-08 (Simulated Ticket Email Modal):** **REAL.** `TicketView.tsx:45,67-69,181-189,554-618`.
